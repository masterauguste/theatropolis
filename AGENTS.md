# Theatropolis — Agent Reference

Reference for AI agents working in this repository. Read this first; it should
save a full re-exploration of the codebase.

## What this is

Theatropolis is a **master–agent manager for sing-box fleets** (proxy servers).
A single master serves a local web UI (fleet, Proxy Node, user, and version
management) and a gRPC control plane; agents enroll with one-time tokens, keep a
long-lived bidirectional stream to the master, and run/supervise sing-box.

- Module: `github.com/masterauguste/theatropolis`, Go 1.26 (`go.mod`).
- Dependencies: gRPC, protobuf, `golang.org/x/crypto` (Argon2id), `x/sys`. Nothing else — stdlib-heavy.
- Releases: Linux amd64/arm64 tarballs on GitHub releases (`theatropolis_linux_{arch}.tar.gz` + RSA-PSS-signed `checksums.txt`). Each archive contains the master, agent, and dedicated update-helper binaries.

## Layout

- `docs/proxy-node-manager-design.md` — implemented product model and
  old-format cutover/reinstallation policy for the Proxy Node manager.
- `internal/proxynode/` — strict schema-v14 store with independent topology and
  user revisions plus the last successfully applied topology, generated
  credentials, tree validation, sing-box fleet compiler, legacy master
  quarantine, and receiver-first fleet deployment orchestration. Topology
  comparison deliberately strips End Users, while the actual restart payload
  overlays a fresh live-user snapshot. The Agent intersects topology-carried
  Membership IDs with its active authority, so delayed topology cannot restore
  a revoked user. Automatic user synchronization uses an independent revisioned
  control command carrying applied/desired/in-flight topology variants; the Agent
  persists this authority and overlays it before topology activation, so a draft
  cannot remain the user authority. Entrance credential-shape changes remain pending until the matching
  topology applies. Match clauses belong to ordered Links and apply to
  all traffic for that Proxy Node reaching the parent Hop; there is no
  per-clause server/inbound/user scope.
- Release catalog note: Theatropolis versions come from GitHub release metadata and are offered only when `checksums.txt`, `checksums.txt.sig`, and both supported Linux tarballs exist. sing-box versions come from `masterauguste/sing-box-v2ray-api-builds` release metadata and are withheld until `build-manifest.json`, the signed manifest, and both version-named Linux archives exist; only stable/RC tags carrying the `theatropolis.N` patch revision at 1.14+ are valid. Installation additionally requires the manifest's tested `traffic-reset-v1` capability alongside live-user management and session revocation. This supersedes the older `releases.go` transport note below.
- Release freshness note: release-version catalogs are never cached; every automatic load and explicit Settings “Check again” action makes a fresh upstream request. Theatropolis entries require both Linux archives plus the signed checksum manifest, so an in-progress tag publication is not exposed as installable.
- Async UI note: the Servers page renders a shell and loads `/servers/content`; its Server settings dialog contains fleet Agent and sing-box update controls. The sing-box selector independently loads the signed catalog from `/servers/versions?catalog=sing-box` and posts a chosen exact version to `/servers/sing-box-update-all`, which queues only connected compatible Agents. The Pool page renders manual-entry controls immediately and loads fleet-derived entries from `/pool/content`. Both use the shared `data-async-region` loader in `app.js` with spinner, retry, empty, error, and expired-session handling. Release catalogs on Settings and server management remain asynchronous and use the same loading-spinner visual. Settings also shows the newest 50 of the bounded non-sensitive accounting failures, newest first, with links to the affected server; the explicit confirmed Clear Log action deletes only this failure history. Keep data required to safely construct mutation forms synchronous; defer independent read-only collections.
- Session persistence note: `/login` is the canonical entry for both administrators and end users. A schema-v3 role-tagged `web-auth.json` under the private master state directory owns one global username namespace and performs one credential lookup; installer upgrades migrate the legacy `/etc/theatropolis/web-auth.json` only after retaining it as a rollback source, and old administrator-only v1/v2 files plus the pre-release `end-user-auth.json` migrate atomically. Any administrator/user username overlap fails closed. Public registration can create only `user` identities. The resolved role issues a realm-specific cookie and CSRF secret, so administrator and portal authorization remain isolated without verifier fallback. Login/logout/invalidation persist synchronously, while routine rolling administrator and end-user activity is updated in memory on every authenticated request and coalesced into background session snapshots at most once per minute. Successful authentication also refreshes the persistent browser cookie to the same seven-day inactivity deadline; there is no separate absolute cutoff. Authentication must never wait for routine session filesystem durability, and activity coalescing is not a request or session rate limit.
- End-user portal note: operator-created Users retain their immutable hidden `usr_...` identity and operator-facing management name. The separate `/portal` authorization realm keeps user identities in the unified role-tagged `web-auth.json` and rolling seven-day browser sessions in `end-user-sessions.json`; neither file enters Proxy Node topology, Agent payloads, subscription tokens, or Membership credentials. Operators create a single-use 24-hour registration link at `/claim/{token}`; successful registration and the deadline both invalidate it, while an explicit administrator reset invalidates a pending token and creates a fresh one. Invalid claim tokens are rejected before Argon2id and claim submissions have an independent per-client anti-abuse limit with no global quota. Reset Login bumps the account auth revision, revokes every portal session, clears the password, and issues a new registration link without rotating configuration-subscription URLs or Node credentials. The portal is read-only and shows only that user's configuration links, Node access, traffic quota, reset time, expiry state, and newest 30 UTC+8 calendar days of traffic. The operator user detail shows the same history with a per-Node breakdown. Daily rows are committed in SQLite with the accepted usage delta, survive quota resets, and cascade away when their Membership is removed. Deleted Users are reconciled out of unified identities and portal sessions at startup.
- Proxy Node compilation inserts sniff immediately before the first ordered domain, geosite/custom rule-set, or protocol match that needs it, and resolve immediately before the first destination-IP, geoip/custom rule-set match. Every active conditional Link owns exactly one Rule; a conditional BLOCK branch instead compiles directly to sing-box Reject on its parent Hop and creates no Link, listener, credential, or child Hop. Link and BLOCK Rules share one explicit first-match order. An optional fallback Link stays last, and otherwise the Hop's Direct/Reject terminal runs. The UI's `ALL` match choice creates or converts that fallback Link without storing a synthetic Rule, allowing unmatched traffic to relay to a child Hop. Every entrance Membership and every Link has a distinct generated credential; compatible logical listeners sharing one Agent socket are coalesced and distinguished by `auth_user`. Adding a Rule to an already-active Link clones its downstream subtree, including any BLOCK branches, into a new sibling Link with fresh Hop/Link/Rule IDs and credentials, so visual branches never share downstream routing context. Schema v4 migrates older multi-Rule Links using the same split-and-clone rule. Shadowsocks mux usage is per Link: requesting parent outbounds explicitly use `smux`, while a coalesced child inbound enables mux support if any attached Link requests it. Padding and TCP Brutal remain schema-compatible but are intentionally not exposed by the guided editor.
- Shared listener note: compatibility and collision detection span every Proxy Node and all supported inbound protocols. Compatible refs reuse listener-owned generated material (`server_key` for Shadowsocks 2022 and `obfs_secret` for Hysteria2) while Membership/Link credentials remain unique. Listener edits are one atomic store mutation across all compatible refs: listener-wide transport/TLS fields propagate, every affected Link credential rotates on a credential-shape change, and affected entrance credentials are staged together. Address family and the basic per-Link Shadowsocks mux toggle remain per Link; inbound mux support is the OR of all attached refs, while hidden padding/Brutal policy is listener-wide. Generated Hysteria2 listeners always set `bbr_profile` to `aggressive`. Shadowsocks claims TCP+UDP, AnyTLS TCP, and Hysteria2 UDP; AnyTLS and Hysteria2 can share a numeric port, but either conflicts with Shadowsocks on the same Agent/address. Store mutations preserve an existing listener's material, and `Open`/`Compile` reconcile older compatible state before rendering. Listener lifetime is reference-derived: removing one shared ref removes only that user/routing identity; the final removal emits an empty managed config for the former Agent so the listener is actually withdrawn.
- Listener editor note: entrance and Link forms expose existing physical listeners on the selected Agent as explicit reuse presets. Selecting one copies only listener-wide protocol/socket/TLS options; relay address family and parent-side Shadowsocks mux stay per Link. Manual mode validates TCP/UDP socket claims and listener compatibility live, while the store remains the authoritative validation boundary. Catalog entries are derived from logical references and must never expose generated server keys, obfuscation secrets, or user credentials.
- Proxy Node overview note: the routing tree is recursive rather than a flat indented list and is the sole topology-management surface; there is no separate Hop manager. Every feasible Link-owned or BLOCK Rule renders as its own numbered route branch labelled with its actual match type and values; selecting that branch edits only that Rule, while dragging sibling branches asynchronously writes an explicit first-match priority across the entire parent Hop without navigating. Hop cards have no editable topology name and display their assigned Agent. The Entrance Hop is the exception to the shared Hop inspector: it opens a dedicated wide dialog that owns entrance Agent, listener/protocol, terminal, and branch creation. The page header owns Users, rename, and deletion; the Proxy Node UI exposes no custom Rule Set manager. A Link branch owns its credential, auth_user, child Hop, downstream context, and child-Agent destination; a BLOCK branch terminates locally with Reject and has no relay artifacts. Duplicating a Link branch clones the subtree with fresh identities while compatible physical listener settings remain shareable. When ancestor constraints hide contradictory Rules from one displayed occurrence of a Hop, the client merges the visible drag order into that Hop's complete Rule order before submitting, so hidden priorities are never lost. The Rule inspector retains keyboard-accessible move buttons. Saving an individual editor returns to the relay map with the inspector closed. Branch creation is Rule-first and atomic: its action either creates the Link and child Hop together or creates a local BLOCK rule. Creating a Proxy Node entrance or child branch also returns to the bare relay-map URL so no inspector opens automatically. Child Hop inspectors own Agent movement, branch creation, and Direct/Reject terminal exit; moving a Hop preserves its identity and complete downstream subtree. The parent Link inspector owns terminal plus fallback mode, deletion, transport/listener settings, and destructive destination replacement. Replacing a destination retains the Link's Rule/fallback/priority, logically deletes the old child subtree, rotates the Link credential, and creates a fresh terminal Hop on the selected Agent in one topology transaction. A visible local Direct/Reject fallback terminal is itself editable and can launch the branch wizard preselected to `ALL` to relay unmatched traffic. The renderer propagates positive ancestor rules plus first-match exclusions, removes branches proven impossible in the displayed path, and marks DNS/remote-Rule-Set/complex-regex relationships as runtime-dependent instead of resolving domains on the master. Fallback Links render once at the bottom unless earlier rules provably cover the path, while ruleless legacy Links remain visibly inactive. A Direct terminal is implicit when its Hop is a true displayed leaf, but remains an explicit fallback node when that Hop has another visible branch; Reject terminals and conditional BLOCK outcomes are always explicit. Proxy Node access is manageable from both the Node and global-user pages; every user-plane mutation queues automatic synchronization and the user page has no manual deploy control. Every completed topology mutation reserves the topology plane, validates the full candidate, deploys it immediately receiver-first, and records the applied snapshot; there is no separate topology Save action. Further topology controls remain locked until success or rollback. The private transaction journal retains the pre-change topology so failure restores the UI state while merging concurrent user-plane changes, then queues the latest user revision. Preserve this plane separation, terminal-placement visibility, and no-op restart avoidance when changing topology UI or deployment orchestration.
- Proxy Node membership UI note: the relay map's wide Users dialog owns the searchable roster, grants, compensation, and membership maintenance dialogs; `/proxy-nodes/{proxy_id}/users` is a compatibility redirect that opens it. A finite subscription remains compensable even when other global users are unassigned. Global-user settings model assignments as compact Node-role chips and use a searchable radio-list picker that exposes only unassigned Nodes, one role at a time so quota/subscription settings remain explicit. Add Node and Add User remain visible after every eligible target is already assigned; their dialogs show a non-mutating empty state while duplicate membership creation remains rejected by the store. A membership reset rotates only that Proxy Node credential; the global user page can atomically rotate every Membership credential without changing the subscription token.
- Dropdown note: shared select popovers clamp to the viewport and wrap long option labels inside their vertically scrollable menu. Large catalogs render option buttons incrementally only while open and release them on close; the native select remains the source of truth. The routing geosite/geoip selector is also a manual top-layer popover (so modal footers cannot cover or clip it), and those two catalog-backed match types are single-select; other match types retain multi-value OR behavior.
- Inbound URI export note: Shadowsocks 2022, AnyTLS, and Hysteria2 share URIs always connect to a resolved agent IP, never the master or TLS hostname. Each user row offers IPv4 and/or IPv6 according to availability; IPv6 authorities are bracketed, while AnyTLS/Hysteria2 keep the configured certificate identity as SNI. Configuration-subscription export is separate: an Agent may optionally publish one IPv4 domain and one IPv6 domain, each of which replaces only that family's IP in Clash/Surge/sing-box subscription Nodes while the entrance certificate identity remains SNI.
- User subscription note: every global user automatically receives one rotatable bearer token with separate Clash, Surge, and sing-box endpoints. Subscription Nodes are derived from that user's enabled or quota-reached Memberships on applied, routable entrances. A quota-reached Node stays in the exported profile with its stable Membership credential, while the independent user plane removes that credential from the live entrance authority; reset re-adds the same credential, so clients need no re-import. At a finite subscription deadline the Membership is atomically removed, its entrance credential is revoked, and its accounting rows are deleted; restoring access requires a new grant and credential. One universal Subscription policy owns the default route and ordered rules for every user export; it never touches the topology or user-deployment planes. Geosite and GeoIP are first-class matches: Clash uses native rules with pinned auto-updating MetaCubeX data URLs, sing-box uses SagerNet binary rule sets, and Surge uses the master's public read-only MetaCubeX-backed `DOMAIN-SET`/CIDR `RULE-SET` adapters. There is no administrator-managed rule-provider model. The only client-side actions are Proxy, Direct, and Reject; Proxy is a selector over each user's exported address-family variants followed by manual Direct and Reject choices. With no Node, Direct remains first/default and Reject remains selectable. Per-user subscription pages show only links and Nodes, the global `/subscriptions` route edits policy, and public feed responses are `no-store`. Resetting a subscription atomically rotates its bearer token and every Membership credential in the same user-plane revision; revocation changes only the token. Neither action changes the universal policy.

- `cmd/theatropolis-master/` — unprivileged master binary. Subcommands: `serve`, `create-enrollment`, `set-web-admin`, `version`; the legacy privileged `apply-update` command fails closed.
- `cmd/theatropolis-agent/` — unprivileged agent binary. The legacy privileged update subcommands fail closed.
- `cmd/theatropolis-update-helper/` — the only project binary intended to run as root. It has no listener, is invoked with fixed arguments by systemd, verifies signed project releases, rejects downgrades, and drops to the agent account before executing a sing-box candidate.
- `internal/control/server.go` — gRPC `AgentControlService`: `Enroll` (token → Ed25519 key binding; replacement redemption swaps the key and disconnects the old session), `Connect` (long-lived bidirectional stream with nonce challenge, monotonic sequence numbers, 10 s initial-hello deadline, 75 s heartbeat timeout). Current Agents advertise `managed-user-traffic-delta-v1`, sample only SSM endpoints containing entrance Membership identities, preserve successful partial endpoint results, and atomically read-and-clear interval counters which the master adds directly; request-capable Agents additionally advertise `managed-user-traffic-request-v1`, allowing the master to request an immediate correlated sample before an entrance-changing topology deployment. A failed destructive sample is recorded and the next 15-second periodic poll is the next attempt; the master does not retry the already-cleared batch. Child-only Agents are excluded. The master maps counters only to memberships whose entrance is on that authenticated Agent and persists bounded non-sensitive accounting-failure history. Legacy `managed-user-traffic-v1` cumulative reports and acknowledgements remain supported only for rolling upgrades. `managed-user-authority-v1` is a separate revisioned command/report path and never consumes a deployment record. Every deploy-capable authenticated connection queues the master's authoritative profile via `profile_sync.go`: retained latest logical config for replacement hardware, otherwise the shared no-listener/reject config. The gRPC server also caps concurrent HTTP/2 streams per connection. Also master-local methods the web UI calls: `QueueValidation`, `QueueDeployment`, `QueueManagedUserAuthority`, `QueueAgentUpdate`, `QueueSingBoxUpdate`, `RevokeAgent`, plus `SessionRegistry`. `QueueValidation`/`QueueDeployment` render pool refs at the boundary (`pool.Render`) — records keep the LOGICAL config, agents only receive rendered JSON + its digest.
- `internal/control/propagation.go` — fleet-wide outbound-pool propagation: renders logical configs, finds dependents (`pool.Refs` over `Store.List`), and re-renders/redeploys them (SHA-deduped, fresh `dep_`/`rev_` IDs via `randomOpaqueID`) on applied deployments, reported-address changes, observed-address changes (IP change ⇒ reconnect ⇒ new XFF), probed-address changes, revocation, and manual pool changes. Offline changes catch up through the unconditional authoritative profile replay on reconnect. `Server.PoolRegistry()` + `Server.PropagateManualPoolChange()` are the webui hooks.
- `internal/control/observed.go`, `probe.go` — pool address sources: the observed control-connection address (XFF last element via Caddy's default `X-Forwarded-For`, fallback gRPC peer addr) and `RequestAddressProbe` + `address_probe_report` handling (probe command gated on online + `address-probe-v1`). Probed-address freshness is agent-side (agents periodically probe families without a routable interface address and report changes); there is no master-side re-probe scheduler. `Server.Close()` remains as an idempotent no-op for the tests that call it. Pool address hierarchy per family: override → observed → probed → interface-reported; refs may pin `"family"` (auto/ipv4/ipv6). A newly reported routable interface family evicts its same-family probe fallback, and a late probe cannot replace it. Only globally routable addresses are used (no RFC1918/ULA/CGNAT/reserved — TEST-NET/documentation ranges deliberately kept), from every source including the override; each package enforces this with its own `globallyRoutable` helper (agent collection, master sanitize/observed/probe-report checks, registry setters as the last gate: `SetReported`/`SetProbed` drop, `SetObserved` ignores, `SetOverride` rejects with `ErrInvalidAddress`).
- `internal/pool/` — outbound-pool registry (`outbound-pool.json`: manual entries with optional display remarks, per-agent reported addresses + independent IPv4/IPv6 overrides, optional per-family configuration-subscription domains, render stamps + `PoolVersion`; the legacy single `address_override` field migrates into its matching family on load, while the removed ambiguous `default_tls_address` is accepted only for decode compatibility and discarded), proxy share-URI conversion (`uri.go`: ss/vmess/vless/trojan/hysteria2/tuic/anytls/SOCKS/HTTP(S)), ref rendering (`Render`/`Refs`, `agent/<id>/<inbound>/<user>` and `manual/<name>` refs, optional per-ref TLS `server` hostname, dead refs → `direct` fallback), and pool-view derivation (`Derive`). Subscription domains are edited atomically in the individual Server settings dialog, do not advance `PoolVersion`, and never become topology/pool destination choices.
- `internal/webui/` — server-rendered HTML UI (embedded templates in `templates/`, assets in `assets/`, Go 1.22 mux patterns). Argon2id password or legacy access key in `web-auth.json`; login failures are limited per client address while Argon2id execution is globally concurrency-limited; `__Host-` session cookie + `X-CSRF-Token` header; sessions persisted to `web-sessions.json` with a rolling seven-day inactivity deadline and no absolute lifetime. `releases.go` reads GitHub release metadata and requires both archives plus the checksum manifest and signature. `rulesets.go` (`RuleSetCatalog`) lists available SagerNet geosite/geoip rule-set names via the GitHub REST git-trees API, persists the last good indexes under `rule-set-catalogs/`, refreshes expired 24 h entries in the background (hourly freshness poll), and serves stale data on upstream errors; the editor reads them from `GET /servers/{agent_id}/rule-set-options?kind=geosite|geoip`. `pool.go` is the fleet outbound pool UI: a dedicated `/pool` page (`templates/pool.html`, nav item between Servers and Settings) whose managed entries collapse every inbound into one clickable summary (server, IPv4/IPv6, protocol, port); its dialog shows the inbound's users/references and independent per-family override form (`POST /servers/{agent_id}/address`) without exposing internal address-source labels. Manual CRUD remains at `POST /pool` and `POST /pool/delete`. On-demand address probes use `POST /servers/{agent_id}/probe-address` (family must be ipv4/ipv6, 202 on accept), while `GET /servers/{agent_id}/pool-options` deliberately remains user-level (options carry per-family `ipv4`/`ipv6` + `available`) so the guided routing editor can select a specific user. The servers table is intentionally compact: server name, binary connection-establishment state, and independently resolved IPv4/IPv6 addresses with no source attribution. The `AgentController` interface exposes `PoolRegistry`/`PropagateManualPoolChange`/`DeploymentRecords`/`RequestAddressProbe` for this. Guided config editor: there is no agent-local outbound manager; ordered draggable route cards select Direct, Reject, or a specific IPv4/IPv6/user reference directly from the fleet pool. Cards scope rules to the whole agent, one inbound, or an authenticated username (`auth_user`, which spans inbounds sharing that username), then select a match type and one or more match values. Geo rule sets are picked with a filterable chip combobox; `route.rule_set` entries for referenced SagerNet sets are auto-derived on save with daily agent-side SRS updates (custom SRS sets pass through untouched; there is no separate rule-set UI). `dropdown.js` progressively enhances every native `<select>` (including dynamically cloned config cards and release catalogs) into the shared keyboard-accessible authored dropdown while keeping the native element as the form/validation source of truth. The closed trigger is selection-only and owns exactly its painted hit area; the open menu contains the localized filter field plus a viewport-aware, internally scrolling option list that keeps keyboard-focused options visible. Target-Agent variants add the newest already-known path latency and protocol to the same primitive; unknown paths remain explicitly unmeasured. Link history opens in its own read-only monitor dialog from the Link/Rule inspector, while relay editors keep only transport controls and an immediate draft probe. Wrap a select in `[data-native-select]` only when native rendering is intentional. Design system: `DESIGN.md` and `UX-CONTRACT.md` define the durable signal-desk system; the single coherent stylesheet (`app.css`) maps it through one cool light token block, with a connected desktop route rail, compact mobile header, system-ui typography, and ui-monospace data. Keep everything token-driven off the single `:root` block; all class names double as JS hooks, so rename nothing without checking `app.js`/`config-editor.js` and `handler_test.go` (it asserts literal header HTML).
- Public web URLs require HTTPS in production. `http://localhost:<port>` is accepted only for local development and must never be generalized to non-localhost hosts or loopback IP literals.
- Web UI localization note: English and Simplified Chinese (`zh-CN`) are first-class locales. `i18n.go` negotiates the first visit from `Accept-Language` with English fallback, persists that result as a one-year preference, and lets the explicit language switch update the same cookie. It parses a localized template set without translating runtime user data and localizes server-generated view labels. `assets/i18n.js` owns client-generated interaction copy used by `app.js`, `dropdown.js`, and `config-editor.js`. Every document uses `.Locale` for `<html lang>`, and the global/login language switch preserves same-origin redirect safety.
- `internal/agent/runner.go` — agent control loop: token enrollment sends only the one-time token and the agent-generated Ed25519 public key, then calls the inactive manager's `ResetForEnrollment`, so another master's persisted profile cannot start. The agent never receives, stores, or sends the master's private server-record ID. On reconnect it sends the public key and proves private-key possession; the master reverse-resolves that key to its server record. The runner connects with backoff (1 s→30 s), sends heartbeats every 20 s, dispatches validate/deploy/update commands, and asynchronously samples the loopback managed-user API on connection, every 15 seconds, and immediately on a correlated master request. Counter frames carry one-shot reset deltas and a fresh compatibility batch epoch; no Agent traffic ledger or acknowledgement exists. Collection failures are reported with a fixed non-sensitive diagnostic without dropping the stream. Generated Link paths are also sampled on connect and every 30 seconds from the parent Agent: AnyTLS/Shadowsocks use TCP connect and Hysteria2 uses a QUIC handshake with its listener obfuscation. Logical Links sharing the same destination address and transport reuse one bounded, concurrency-limited physical probe whose result fans out to their generated outbound tags. The master stores five-minute aggregates for 30 days keyed to the physical path; deleting a Link removes its UI access but not shared history, which expires naturally. Heartbeats report interface addresses only (globally routable ones — no RFC1918/ULA/CGNAT/reserved; a private-only host reports nothing and relies on probes). `probe.go` (`Probe` + `ProbeScheduler`): public-IP discovery via plain-text IP echo endpoints (api4/api6.ipify.org, ipv4/ipv6.icanhazip.com), answered with `address_probe_report` (async via a channel so the control loop never blocks). On-demand probes run when the master sends `probe_addresses` (capability `address-probe-v1`); additionally the per-session scheduler probes Komari-style on the heartbeat tick for any family with NO globally-routable interface address (5 min interval, family-locked `tcp4`/`tcp6` dialer so a v4 probe never egresses via v6), reporting only changes — direct-attach hosts never generate probe traffic, and successful on-demand results reset both the scheduler's dedup state and that family's five-minute attempt timer (`noteProbed`). `Runner.Prober` overrides the scheduler in tests (negative `Interval` disables periodic probing).
- Configuration deploy submissions use a fetch/JSON status flow so the first deployment stays on the editor page while validation and activation finish. The guided TLS editor's self-signed mode accepts a domain or IP SAN and emits reserved relative certificate paths; the agent signs and retains the pair, and the master never receives the private key.
- `internal/singbox/` — `manager.go` validates, persists `sing-box/active.json`, supervises sing-box as non-root, and detects users-only candidates; `managed_user_authority.go` persists the newest user revision in `sing-box/user-authority.json` and overlays the matching topology shape before activation. If an older service-less active profile cannot accept persisted authority during startup, sing-box stays fail-closed but the Agent supervisor and control connection remain available so the master's unconditional authoritative replay can repair it. `managed_users.go` replaces complete desired user sets and atomically reads-and-clears interval traffic counters through the patched SSM API without restarting when routing/topology is unchanged, otherwise the existing restart/rollback path remains authoritative. Traffic collection first inspects the active configuration for generated entrance Membership identities: empty entrances, relay-only Agents, and older service-less profiles make no SSM request, while any profile that actually contains a Membership still requires a valid loopback service and fails closed if it is absent. The master likewise records accounting failures only for Agents currently hosting an applied entrance with an enabled Membership, so stale/older relay-only Agent reports cannot pollute the audit history. The Agent keeps no traffic ledger; startup removes the obsolete `traffic-ledger.json` from earlier versions. Do not enable the upstream SSM `cache_path`: it restores cached user credentials as well as counters and can resurrect a disabled/revoked user. The generated API is fixed to `127.0.0.1:19090`, that port is reserved from proxy inbounds, and public SSM API bindings fail policy validation. Enrollment removes inactive config, the old-master-scoped authority, and managed self-signed keys before startup. `validator.go` scrubs secrets from diagnostics, `self_signed.go` owns agent-local ECDSA certificates, and `executable.go` requires sing-box ≥ 1.14 plus both Theatropolis managed-user build tags before exposing deployment/accounting capabilities.
- `internal/agentupdate/`, `internal/singboxupdate/` — self-update. File-based handshake: a bounded request in the service-owned state directory triggers a root systemd path/service pair whose fixed command invokes `theatropolis-update-helper`. Project archives require an RSA-PSS-signed checksum manifest, exact SHA-256 match, safe archive shape, and non-downgrade version; the helper atomically replaces the service and itself. singboxupdate accepts only stable/RC `theatropolis.N` builds and verifies the RSA-PSS signature, signed build-manifest digest, required managed-user/session-revocation capabilities, GitHub asset digests, archive shape, and both required binary build tags before atomically installing `sing-box` + `libcronet.so`.
- `internal/deployment/` — deployment `Record` + 10-status state machine; `MemoryStore`/`DiskStore`; **only latest deployment per agent kept** (one JSON per agent under `<state-dir>/deployments/`). A new candidate inherits the exact last-applied config/revision/digest, so failure and reconnect never promote the candidate. `Record.ConfigJSON`/`ConfigSHA256` are the logical config (may hold pool refs); `RenderedSHA256` is the effective digest actually materialized by the Agent (which can exclude stale topology-carried Memberships). `Store.List` feeds the propagation scan.
- `internal/identity/` — master registry (`identities.json`, 0600): SHA-256 of pending tokens + enrolled Ed25519 public keys only. The master keeps a private server-record ID for UI/configuration purposes. Enrollment resolves it solely from the single-use token; reconnects resolve it from the proved public key. The ID never crosses the agent protocol and is never persisted by the agent. An explicit replacement enrollment may coexist with the current public key; that key remains valid until token redemption atomically swaps it. Server-record ID format `[a-zA-Z0-9][a-zA-Z0-9._-]{0,127}`.
- `api/proto/theatropolis/control/v1/control.proto` — one service, two RPCs (`Enroll`, `Connect` stream). Frames: monotonic `sequence` + `oneof payload`. Protocol version constant = 2; legacy agent-ID fields are reserved and cannot be reused. Generated code in `api/gen/` (regenerate with protoc + protoc-gen-go / protoc-gen-go-grpc, binaries in `.tools/bin/`).
- `install.sh` (~1280 lines, POSIX sh) — installer. Roles `master` / `agent` / `all`. Root + Debian/Ubuntu + systemd only. Agent installs accept only the master address and enrollment token as control-plane identity inputs; the all-in-one role uses `--server` to select the private master-side server record. Master/all installs interactively request the public domain and Caddy HTTPS port from `/dev/tty`; those values are not command-line options. Verifies an RSA-PSS-signed checksum manifest before executing or installing project release binaries, pins `1.14.0-rc.1.theatropolis.2` by hardcoded architecture hashes, and verifies both required binary tags. It creates system users and heavily sandboxed systemd units (main + three `.path`/`.service` update pairs). Existing installations must rerun it once to migrate update units to the dedicated helper. Extensive rollback on failure.
- `tests/*.sh` — installer test suite (master, agent-token, release-tag, security).

## Runtime architecture (installed system)

- Master `serve` opens **three loopback-only listeners**: gRPC `127.0.0.1:8081` (h2c), web UI `127.0.0.1:8080`, Unix socket `/run/theatropolis/master-admin.sock` (0600, local admin API for `create-enrollment`). **TLS is not in the Go process** — Caddy terminates TLS on :8443 (gRPC paths → h2c :8081, rest → :8080), ACME HTTP-01 needs port 80 free.
- Agent connects out with TLS 1.3 only.
- Master state dir adds schema-v14 `proxy-node-state.json` for topology, user policy, independent revisions, conditional BLOCK branches, per-user subscription tokens, the universal subscription routing policy, and the applied topology snapshot, plus `proxy-node-accounting.sqlite` (SQLite WAL, synchronous FULL, private files) as the durable authority for high-frequency Membership usage, rolling-period boundaries, legacy cumulative baselines, and bounded non-sensitive accounting failures. All subscription, quota, compensation, and billing-calendar references use a fixed UTC+8 clock; protocol timestamps remain absolute instants. Schema-v7 JSON accounting is imported into SQL exactly once; schema-v8 UTC calendar dates and accounting-schema-v1 period boundaries migrate to the same calendar labels at UTC+8, while inclusive calendar-month subscription dates become exclusive deadlines without changing their last valid day. Schema-v11 preview state promotes its most recently edited per-user routing policy to the universal policy and enables missing user tokens; schema-v12 preview state removes remote providers and any rules that depended on them. A corrupt accounting database fails closed rather than becoming an empty ledger. Traffic increments and the UTC+8 midnight rolling reset are SQL transactions; minute/hour/day/calendar-month subscription deadlines are checked once per minute. Expired Memberships are atomically deleted with their accounting rows and omitted from active user authority. Manual traffic reset first requests and persists an entrance sample, then clears only usage without moving reset timing. Credential rotation and subscription extension are immediate user-plane operations; extension is additive to a live stored deadline and never changes quota timing. Proxy Node-wide compensation uses a UTC+8 outage start/end range to preselect overlapping active finite subscription intervals, permits explicit checklist overrides, and atomically extends only the selected Membership IDs; unlimited and expired Memberships are excluded. `proxy-node-topology-transaction.json` is a temporary private fleet rollback journal; a master restart clears a committed transaction or restores every touched Agent in the previous topology's recorded receiver-first order before accepting another Proxy Node deployment. Schema-v4 grants migrate as unlimited and non-expiring; schema-v5 state initializes its applied snapshot from the previously desired topology. On first cutover, legacy deployment records move under `legacy-config-quarantine/` before an empty new store is created.
- Agent state dir adds `sing-box/config-state.json` and revisioned `sing-box/user-authority.json`; current Agents keep no traffic ledger and remove the obsolete file on startup. A production Agent without the generation marker quarantines legacy `active.json` and managed certificates before advertising `proxy-node-config-v1`; valid markers are stamped with the running Agent version after startup.
- Update capability gated on systemd path units (`/etc/systemd/system/theatropolis-*-update.path`).
- Root helper: `/usr/local/libexec/theatropolis/theatropolis-update-helper`; it is root-owned and never network-facing.

## Build & test workflow (IMPORTANT: Windows host, use WSL)

This repo is developed on Windows but targets Linux. **Use WSL for Go work:**

- Go 1.26.6 for Linux lives in WSL at `~/go-toolchain/go/bin/go` (not on PATH).
- A Windows Go also exists at `.tools/go/bin/go.exe` for quick checks, but tests assume Linux semantics.
- The repo is visible in WSL at `/mnt/c/Users/Liukun Zhao/Documents/Theatropolis`.

Typical verification (mirrors CI in `.github/workflows/ci.yml`):

```sh
# Go build + tests + vet (run inside WSL):
wsl -- bash -c 'cd "/mnt/c/Users/Liukun Zhao/Documents/Theatropolis" && export PATH="$HOME/go-toolchain/go/bin:$PATH" && go build ./... && go test -count=1 ./... && go vet ./...'

# Installer shell tests: use the helper script (avoids quoting pitfalls below):
MSYS_NO_PATHCONV=1 wsl -- sh "/mnt/c/Users/Liukun Zhao/Documents/Theatropolis/.tools/run-shell-tests.sh"
```

### Git Bash → WSL pitfalls (learned the hard way)

- Prefix WSL commands with `MSYS_NO_PATHCONV=1`, or Git Bash rewrites `/mnt/c/...` arguments into `C:/Program Files/Git/mnt/c/...`.
- Shell `for` loops with globs passed through `wsl -- bash -c '...'` get mangled (loop var expands empty). Put multi-line shell logic in a script file (see `.tools/run-shell-tests.sh`) and invoke that instead.
- **Controlling-terminal gotcha:** `wsl -- sh ...` allocates a pty, so WSL processes have a controlling terminal. `tests/installer-security.sh` has a scenario that requires *no* controlling terminal (installer must fail closed when a token can't be prompted); run plainly, the installer legitimately prompts on `/dev/tty` and the test blocks forever at `install.sh:214`. Run installer tests detached: `setsid --fork --wait sh tests/installer-security.sh </dev/null` (the `.tools/run-shell-tests.sh` helper already does this). All four installer tests pass this way.

## Master migration

- `internal/mastermigration/` creates an encrypted ZIP (Argon2id + XChaCha20-Poly1305) from controlled snapshots of Proxy Node JSON/accounting SQLite, enrolled Agent public keys, deployment records, pool state, and end-user login identities. Pending enrollments, administrator credentials, browser sessions, caches, and system TLS/Caddy state are excluded. Restore is allowed only on a fleet-empty Master, merges imported user identities with the new Master administrator, validates the complete staged state, and swaps it before runtime stores open; the prior files remain in a private rollback directory.
- The Settings helper sends `master-migration-v1` only to connected compatible Agents. Each Agent persists the new `host:port` in its own state directory, acknowledges, exits, and reconnects after systemd restart. Offline/old Agents are deliberately untouched, and a normal token enrollment removes any persisted override.

## Conventions to preserve
