# Theatropolis — Agent Reference

Reference for AI agents working in this repository. Read this first; it should
save a full re-exploration of the codebase.

## What this is

Theatropolis is a **master–agent manager for sing-box fleets** (proxy servers).
A single master serves a local web UI (fleet, Proxy Node, user, and version
management) and a gRPC control plane; agents enroll with one-time tokens, keep a
long-lived bidirectional stream to the master, and run/supervise sing-box.

- Module: `github.com/masterauguste/theatropolis`, Go 1.26 (`go.mod`).
- Dependencies: gRPC, protobuf, `golang.org/x/crypto` (Argon2id), `x/sys`. Nothing else — stdlib-heavy.
- Releases: Linux amd64/arm64 tarballs on GitHub releases (`theatropolis_linux_{arch}.tar.gz` + RSA-PSS-signed `checksums.txt`). Each archive contains the master, agent, and dedicated update-helper binaries.

## Layout

- `docs/proxy-node-manager-design.md` — implemented product model and
  old-format cutover/reinstallation policy for the Proxy Node manager.
- `internal/proxynode/` — strict versioned topology/user store, generated
  credentials, tree validation, sing-box fleet compiler, legacy master
  quarantine, and receiver-first fleet deployment orchestration. Match clauses
  belong to ordered Links and apply to all traffic for that Proxy Node reaching
  the parent Hop; there is no per-clause server/inbound/user scope.
- Release catalog note: Theatropolis versions now come from GitHub release metadata and are offered only when `checksums.txt`, `checksums.txt.sig`, and both supported Linux tarballs exist; only the sing-box catalog continues to use Git `info/refs`. This supersedes the older `releases.go` transport note below.
- Release freshness note: release-version catalogs are never cached; every automatic load and explicit Settings “Check again” action makes a fresh upstream request. Theatropolis entries require both Linux archives plus the signed checksum manifest, so an in-progress tag publication is not exposed as installable.
- Async UI note: the Servers page renders a shell and loads `/servers/content`; the Pool page renders manual-entry controls immediately and loads fleet-derived entries from `/pool/content`. Both use the shared `data-async-region` loader in `app.js` with spinner, retry, empty, error, and expired-session handling. Release catalogs on Settings and server management remain asynchronous and use the same loading-spinner visual. Keep data required to safely construct mutation forms synchronous; defer independent read-only collections.
- Session persistence note: login/logout/invalidation persist synchronously, while routine rolling activity is updated in memory on every authenticated request and coalesced into a background `web-sessions.json` snapshot at most once per minute. Successful authentication also refreshes the persistent browser cookie to the same seven-day inactivity deadline; there is no separate absolute cutoff. Authentication must never wait for routine session filesystem durability.
- Proxy Node compilation inserts sniff immediately before the first Link-owned domain, geosite/custom rule-set, or protocol match that needs it, and resolve immediately before the first destination-IP, geoip/custom rule-set match. Every active conditional Link owns exactly one Rule; sibling Rules are evaluated in explicit global order, an optional fallback Link stays last, and otherwise the Hop's Direct/Reject terminal runs. The UI's `ALL` match choice creates or converts that fallback Link without storing a synthetic Rule, allowing unmatched traffic to relay to a child Hop. Every entrance Membership and every Link has a distinct generated credential; compatible logical listeners sharing one Agent socket are coalesced and distinguished by `auth_user`. Adding a Rule to an already-active Link clones its downstream subtree into a new sibling Link with fresh Hop/Link/Rule IDs and credentials, so visual branches never share downstream routing context. Schema v4 migrates older multi-Rule Links using the same split-and-clone rule. Shadowsocks mux usage is per Link: requesting parent outbounds explicitly use `smux`, while a coalesced child inbound enables mux support if any attached Link requests it. Padding and TCP Brutal remain schema-compatible but are intentionally not exposed by the guided editor.
- Shared listener note: compatibility and collision detection span every Proxy Node and all supported inbound protocols. Compatible refs reuse listener-owned generated material (`server_key` for Shadowsocks 2022 and `obfs_secret` for Hysteria2) while Membership/Link credentials remain unique. A difference in the basic per-Link Shadowsocks mux toggle does not split the listener; inbound mux support is the OR of all attached refs, while hidden padding/Brutal policy remains listener-wide and must match. Generated Hysteria2 listeners always set `bbr_profile` to `aggressive`. Shadowsocks claims TCP+UDP, AnyTLS TCP, and Hysteria2 UDP; AnyTLS and Hysteria2 can share a numeric port, but either conflicts with Shadowsocks on the same Agent/address. Store mutations preserve an existing listener's material, and `Open`/`Compile` reconcile older compatible state before rendering. Listener lifetime is reference-derived: removing one shared ref removes only that user/routing identity; the final removal emits an empty managed config for the former Agent so the listener is actually withdrawn.
- Proxy Node overview note: the routing tree is recursive rather than a flat indented list and is the sole topology-management surface; there is no separate Hop manager. Every feasible Link-owned Rule renders as its own numbered route branch labelled with its actual match type and values; selecting that branch edits only that Rule, while dragging sibling branches asynchronously writes an explicit first-match priority across the entire parent Hop without navigating. Each visible conditional branch is one logical Link with its own credential, auth_user, child Hop, and downstream context; duplicating it clones the subtree with fresh identities while compatible physical listener settings remain shareable. When ancestor constraints hide contradictory Rules from one displayed occurrence of a Hop, the client merges the visible drag order into that Hop's complete Rule order before submitting, so hidden priorities are never lost. The Rule inspector retains keyboard-accessible move buttons. Saving returns to the relay map with the inspector closed. Branch creation is Rule-first and atomic: it creates the Link and child Hop together, and deletion removes the child subtree. Creating a Proxy Node entrance or child branch also returns to the bare relay-map URL so no inspector opens automatically. A Hop inspector exposes only branch creation and moving the Hop to a different Agent. The parent Link inspector owns the child terminal plus fallback mode, deletion, child-Hop navigation, and transport/listener settings; the entrance terminal lives under Entrance configuration. A visible local Direct/Reject fallback terminal is itself editable and can launch the branch wizard preselected to `ALL` to relay unmatched traffic. The renderer propagates positive ancestor rules plus first-match exclusions, removes branches proven impossible in the displayed path, and marks DNS/remote-Rule-Set/complex-regex relationships as runtime-dependent instead of resolving domains on the master. Fallback Links render once at the bottom unless earlier rules provably cover the path, while ruleless legacy Links remain visibly inactive. A Direct terminal is implicit when its Hop is a true displayed leaf, but remains an explicit fallback node when that Hop has another visible branch; Reject terminals are always explicit. Proxy Node access is granted/revoked only from each global user's settings, where assigned Nodes are compact detail-dialog tags, unassigned Nodes use the shared searchable dropdown, and pending access changes can be deployed directly. Fleet deployment compares compiled SHA-256 digests with the latest applied rendered digest and skips unchanged Agents; receiver-first ordering and availability checks apply only to changed Agents. Preserve this ownership, terminal-placement visibility, and no-op restart avoidance when changing topology UI or deployment orchestration.
- Dropdown note: shared select popovers clamp to the viewport and wrap long option labels inside their vertically scrollable menu. The routing geosite/geoip selector is also a manual top-layer popover (so modal footers cannot cover or clip it), and those two catalog-backed match types are single-select; other match types retain multi-value OR behavior.
- Inbound URI export note: Shadowsocks 2022, AnyTLS, and Hysteria2 share URIs always connect to a resolved agent IP, never the master or TLS hostname. Each user row offers IPv4 and/or IPv6 according to availability; IPv6 authorities are bracketed, while AnyTLS/Hysteria2 keep the configured certificate identity as SNI.

- `cmd/theatropolis-master/` — unprivileged master binary. Subcommands: `serve`, `create-enrollment`, `set-web-admin`, `version`; the legacy privileged `apply-update` command fails closed.
- `cmd/theatropolis-agent/` — unprivileged agent binary. The legacy privileged update subcommands fail closed.
- `cmd/theatropolis-update-helper/` — the only project binary intended to run as root. It has no listener, is invoked with fixed arguments by systemd, verifies signed project releases, rejects downgrades, and drops to the agent account before executing a sing-box candidate.
- `internal/control/server.go` — gRPC `AgentControlService`: `Enroll` (token → Ed25519 key binding; replacement redemption swaps the key and disconnects the old session), `Connect` (long-lived bidirectional stream with nonce challenge, monotonic sequence numbers, 10 s initial-hello deadline, 75 s heartbeat timeout). Every deploy-capable authenticated connection queues the master's authoritative profile via `profile_sync.go`: retained latest logical config for replacement hardware, otherwise the shared no-listener/reject config. The gRPC server also caps concurrent HTTP/2 streams per connection. Also master-local methods the web UI calls: `QueueValidation`, `QueueDeployment`, `QueueAgentUpdate`, `QueueSingBoxUpdate`, `RevokeAgent`, plus `SessionRegistry`. `QueueValidation`/`QueueDeployment` render pool refs at the boundary (`pool.Render`) — records keep the LOGICAL config, agents only receive rendered JSON + its digest.
- `internal/control/propagation.go` — fleet-wide outbound-pool propagation: renders logical configs, finds dependents (`pool.Refs` over `Store.List`), and re-renders/redeploys them (SHA-deduped, fresh `dep_`/`rev_` IDs via `randomOpaqueID`) on applied deployments, reported-address changes, observed-address changes (IP change ⇒ reconnect ⇒ new XFF), probed-address changes, revocation, and manual pool changes. Offline changes catch up through the unconditional authoritative profile replay on reconnect. `Server.PoolRegistry()` + `Server.PropagateManualPoolChange()` are the webui hooks.
- `internal/control/observed.go`, `probe.go` — pool address sources: the observed control-connection address (XFF last element via Caddy's default `X-Forwarded-For`, fallback gRPC peer addr) and `RequestAddressProbe` + `address_probe_report` handling (probe command gated on online + `address-probe-v1`). Probed-address freshness is agent-side (agents periodically probe families without a routable interface address and report changes); there is no master-side re-probe scheduler. `Server.Close()` remains as an idempotent no-op for the tests that call it. Pool address hierarchy per family: override → observed → probed → interface-reported; refs may pin `"family"` (auto/ipv4/ipv6). A newly reported routable interface family evicts its same-family probe fallback, and a late probe cannot replace it. Only globally routable addresses are used (no RFC1918/ULA/CGNAT/reserved — TEST-NET/documentation ranges deliberately kept), from every source including the override; each package enforces this with its own `globallyRoutable` helper (agent collection, master sanitize/observed/probe-report checks, registry setters as the last gate: `SetReported`/`SetProbed` drop, `SetObserved` ignores, `SetOverride` rejects with `ErrInvalidAddress`).
- `internal/pool/` — outbound-pool registry (`outbound-pool.json`: manual entries with optional display remarks, per-agent reported addresses + independent IPv4/IPv6 overrides, optional default TLS hostname, render stamps + `PoolVersion`; the legacy single `address_override` field migrates into its matching family on load), proxy share-URI conversion (`uri.go`: ss/vmess/vless/trojan/hysteria2/tuic/anytls/SOCKS/HTTP(S)), ref rendering (`Render`/`Refs`, `agent/<id>/<inbound>/<user>` and `manual/<name>` refs, optional per-ref TLS `server` hostname, dead refs → `direct` fallback), and pool-view derivation (`Derive`). The default TLS hostname is entered at enrollment and editable in the individual server settings dialog; it is offered as the preferred AnyTLS/Hysteria2 destination while IPv4/IPv6 remain selectable.
- `internal/webui/` — server-rendered HTML UI (embedded templates in `templates/`, assets in `assets/`, Go 1.22 mux patterns). Argon2id password or legacy access key in `web-auth.json`; login failures are limited per client address while Argon2id execution is globally concurrency-limited; `__Host-` session cookie + `X-CSRF-Token` header; sessions persisted to `web-sessions.json` with a rolling seven-day inactivity deadline and no absolute lifetime. `releases.go` reads GitHub release metadata and requires both archives plus the checksum manifest and signature. `rulesets.go` (`RuleSetCatalog`) lists available SagerNet geosite/geoip rule-set names via the GitHub REST git-trees API, persists the last good indexes under `rule-set-catalogs/`, refreshes expired 24 h entries in the background (hourly freshness poll), and serves stale data on upstream errors; the editor reads them from `GET /servers/{agent_id}/rule-set-options?kind=geosite|geoip`. `pool.go` is the fleet outbound pool UI: a dedicated `/pool` page (`templates/pool.html`, nav item between Servers and Settings) whose managed entries collapse every inbound into one clickable summary (server, IPv4/IPv6, protocol, port); its dialog shows the inbound's users/references and independent per-family override form (`POST /servers/{agent_id}/address`) without exposing internal address-source labels. Manual CRUD remains at `POST /pool` and `POST /pool/delete`. On-demand address probes use `POST /servers/{agent_id}/probe-address` (family must be ipv4/ipv6, 202 on accept), while `GET /servers/{agent_id}/pool-options` deliberately remains user-level (options carry per-family `ipv4`/`ipv6` + `available`) so the guided routing editor can select a specific user. The servers table is intentionally compact: server name, binary connection-establishment state, and independently resolved IPv4/IPv6 addresses with no source attribution. The `AgentController` interface exposes `PoolRegistry`/`PropagateManualPoolChange`/`DeploymentRecords`/`RequestAddressProbe` for this. Guided config editor: there is no agent-local outbound manager; ordered draggable route cards select Direct, Reject, or a specific IPv4/IPv6/user reference directly from the fleet pool. Cards scope rules to the whole agent, one inbound, or an authenticated username (`auth_user`, which spans inbounds sharing that username), then select a match type and one or more match values. Geo rule sets are picked with a filterable chip combobox; `route.rule_set` entries for referenced SagerNet sets are auto-derived on save with daily agent-side SRS updates (custom SRS sets pass through untouched; there is no separate rule-set UI). `dropdown.js` progressively enhances every native `<select>` (including dynamically cloned config cards and release catalogs) into the shared keyboard-accessible, type-to-filter text-field dropdown while keeping the native element as the form/validation source of truth; long option lists have a viewport-aware maximum height, scroll internally without closing, and keep keyboard-focused options visible. Wrap a select in `[data-native-select]` only when native rendering is intentional. Design system: single coherent stylesheet (`app.css`), warm parchment/burgundy palette, system fonts only (body system-ui, headings Georgia serif, code ui-monospace) — keep everything token-driven off the single `:root` block; all class names double as JS hooks, so rename nothing without checking `app.js`/`config-editor.js` and `handler_test.go` (it asserts literal header HTML).
- `internal/agent/runner.go` — agent control loop: token enrollment sends only the one-time token and the agent-generated Ed25519 public key, then calls the inactive manager's `ResetForEnrollment`, so another master's persisted profile cannot start. The agent never receives, stores, or sends the master's private server-record ID. On reconnect it sends the public key and proves private-key possession; the master reverse-resolves that key to its server record. The runner connects with backoff (1 s→30 s), sends heartbeats every 20 s, and dispatches validate/deploy/update commands. Heartbeats report interface addresses only (globally routable ones — no RFC1918/ULA/CGNAT/reserved; a private-only host reports nothing and relies on probes). `probe.go` (`Probe` + `ProbeScheduler`): public-IP discovery via plain-text IP echo endpoints (api4/api6.ipify.org, ipv4/ipv6.icanhazip.com), answered with `address_probe_report` (async via a channel so the control loop never blocks). On-demand probes run when the master sends `probe_addresses` (capability `address-probe-v1`); additionally the per-session scheduler probes Komari-style on the heartbeat tick for any family with NO globally-routable interface address (5 min interval, family-locked `tcp4`/`tcp6` dialer so a v4 probe never egresses via v6), reporting only changes — direct-attach hosts never generate probe traffic, and successful on-demand results reset both the scheduler's dedup state and that family's five-minute attempt timer (`noteProbed`). `Runner.Prober` overrides the scheduler in tests (negative `Interval` disables periodic probing).
- Configuration deploy submissions use a fetch/JSON status flow so the first deployment stays on the editor page while validation and activation finish. The guided TLS editor's self-signed mode accepts a domain or IP SAN and emits reserved relative certificate paths; the agent signs and retains the pair, and the master never receives the private key.
- `internal/singbox/` — `manager.go` (validates, persists `sing-box/active.json`, supervises sing-box child as non-root, restart backoff, rollback, and removes inactive `active.json` plus managed self-signed keys on successful enrollment before startup), `validator.go` (`sing-box check`, scrubs secrets from diagnostics, 4 MiB config / 8 KiB diagnostic limits), `self_signed.go` (generates/reuses agent-local ECDSA self-signed pairs only for reserved editor-emitted paths), `policy.go` (rejects `listen_port` 80 — reserved for ACME, and owns the shared disabled no-listener/reject profile), `executable.go` (requires sing-box ≥ 1.14). Validation and runtime use the agent state directory as their working directory so reserved relative certificate paths work with custom state directories.
- `internal/agentupdate/`, `internal/singboxupdate/` — self-update. File-based handshake: a bounded request in the service-owned state directory triggers a root systemd path/service pair whose fixed command invokes `theatropolis-update-helper`. Project archives require an RSA-PSS-signed checksum manifest, exact SHA-256 match, safe archive shape, and non-downgrade version; the helper atomically replaces the service and itself. singboxupdate checks GitHub's asset digest and archive shape, then validates candidate code under the unprivileged agent identity before atomically installing `sing-box` + `libcronet.so`.
- `internal/deployment/` — deployment `Record` + 10-status state machine; `MemoryStore`/`DiskStore`; **only latest deployment per agent kept** (one JSON per agent under `<state-dir>/deployments/`). `Record.ConfigJSON`/`ConfigSHA256` are the logical config (may hold pool refs); `RenderedSHA256` is the digest of the rendered config the agent received — zero for pre-pool records, where `Record.RenderedDigest()` falls back to `ConfigSHA256`. `Store.List` feeds the propagation scan.
- `internal/identity/` — master registry (`identities.json`, 0600): SHA-256 of pending tokens + enrolled Ed25519 public keys only. The master keeps a private server-record ID for UI/configuration purposes. Enrollment resolves it solely from the single-use token; reconnects resolve it from the proved public key. The ID never crosses the agent protocol and is never persisted by the agent. An explicit replacement enrollment may coexist with the current public key; that key remains valid until token redemption atomically swaps it. Server-record ID format `[a-zA-Z0-9][a-zA-Z0-9._-]{0,127}`.
- `api/proto/theatropolis/control/v1/control.proto` — one service, two RPCs (`Enroll`, `Connect` stream). Frames: monotonic `sequence` + `oneof payload`. Protocol version constant = 2; legacy agent-ID fields are reserved and cannot be reused. Generated code in `api/gen/` (regenerate with protoc + protoc-gen-go / protoc-gen-go-grpc, binaries in `.tools/bin/`).
- `install.sh` (~1280 lines, POSIX sh) — installer. Roles `master` / `agent` / `all`. Root + Debian/Ubuntu + systemd only. Agent installs accept only the master address and enrollment token as control-plane identity inputs; the all-in-one role uses `--server` to select the private master-side server record. Master/all installs interactively request the public domain and Caddy HTTPS port from `/dev/tty`; those values are not command-line options. Verifies an RSA-PSS-signed checksum manifest before executing or installing project release binaries, installs pinned sing-box 1.14.0-beta.2 by hardcoded hash, creates system users, and installs heavily sandboxed systemd units (main + three `.path`/`.service` update pairs). Existing installations must rerun it once to migrate update units to the dedicated helper. Extensive rollback on failure.
- `tests/*.sh` — installer test suite (master, agent-token, release-tag, security).

## Runtime architecture (installed system)

- Master `serve` opens **three loopback-only listeners**: gRPC `127.0.0.1:8081` (h2c), web UI `127.0.0.1:8080`, Unix socket `/run/theatropolis/master-admin.sock` (0600, local admin API for `create-enrollment`). **TLS is not in the Go process** — Caddy terminates TLS on :8443 (gRPC paths → h2c :8081, rest → :8080), ACME HTTP-01 needs port 80 free.
- Agent connects out with TLS 1.3 only.
- Master state dir adds `proxy-node-state.json`, whose strict envelope records `schema`, `schema_version`, and `last_used_by`. On first cutover, legacy deployment records move under `legacy-config-quarantine/` before an empty new store is created.
- Agent state dir adds `sing-box/config-state.json`. A production Agent without that generation marker quarantines legacy `active.json` and managed certificates before advertising `proxy-node-config-v1`; valid markers are stamped with the running Agent version after startup.
- Update capability gated on systemd path units (`/etc/systemd/system/theatropolis-*-update.path`).
- Root helper: `/usr/local/libexec/theatropolis/theatropolis-update-helper`; it is root-owned and never network-facing.

## Build & test workflow (IMPORTANT: Windows host, use WSL)

This repo is developed on Windows but targets Linux. **Use WSL for Go work:**

- Go 1.26.6 for Linux lives in WSL at `~/go-toolchain/go/bin/go` (not on PATH).
- A Windows Go also exists at `.tools/go/bin/go.exe` for quick checks, but tests assume Linux semantics.
- The repo is visible in WSL at `/mnt/c/Users/Liukun Zhao/Documents/Theatropolis`.

Typical verification (mirrors CI in `.github/workflows/ci.yml`):

```sh
# Go build + tests + vet (run inside WSL):
wsl -- bash -c 'cd "/mnt/c/Users/Liukun Zhao/Documents/Theatropolis" && export PATH="$HOME/go-toolchain/go/bin:$PATH" && go build ./... && go test -count=1 ./... && go vet ./...'

# Installer shell tests: use the helper script (avoids quoting pitfalls below):
MSYS_NO_PATHCONV=1 wsl -- sh "/mnt/c/Users/Liukun Zhao/Documents/Theatropolis/.tools/run-shell-tests.sh"
```

### Git Bash → WSL pitfalls (learned the hard way)

- Prefix WSL commands with `MSYS_NO_PATHCONV=1`, or Git Bash rewrites `/mnt/c/...` arguments into `C:/Program Files/Git/mnt/c/...`.
- Shell `for` loops with globs passed through `wsl -- bash -c '...'` get mangled (loop var expands empty). Put multi-line shell logic in a script file (see `.tools/run-shell-tests.sh`) and invoke that instead.
- **Controlling-terminal gotcha:** `wsl -- sh ...` allocates a pty, so WSL processes have a controlling terminal. `tests/installer-security.sh` has a scenario that requires *no* controlling terminal (installer must fail closed when a token can't be prompted); run plainly, the installer legitimately prompts on `/dev/tty` and the test blocks forever at `install.sh:214`. Run installer tests detached: `setsid --fork --wait sh tests/installer-security.sh </dev/null` (the `.tools/run-shell-tests.sh` helper already does this). All four installer tests pass this way.

## CI & release

- `.github/workflows/ci.yml` (branch pushes/PRs; tag pushes are excluded): `go mod verify`, `go test -count=1 ./...`, `go vet`, `sh -n install.sh`, all four `tests/*.sh`, shellcheck; plus linux amd64/arm64 cross-build job.
- `.github/workflows/release.yml` (tags `v*`): same checks, then reproducible three-binary tarballs (`-trimpath`, `-ldflags "-s -w -buildid= -X main.version=… -X main.commit=… -X main.buildDate=…"`, sorted tar with fixed mtime) for amd64/arm64, RSA-PSS-signs `checksums.txt` using the protected `release-signing` environment, and refuses to overwrite an existing release. All binaries are staged under `RUNNER_TEMP` until Go builds finish so earlier untracked artifacts cannot contaminate later binaries with `vcs.modified=true`. See `RELEASING.md`.
- Release teardown note: `TestObservedAddressAndProbeReportEndToEnd` closes both raw client streams and waits for the server handlers to unregister before `TempDir` cleanup. This barrier must remain because deployment-report status can become applied before pool render-stamp persistence finishes.
- Pinned action SHAs in workflows; sing-box versions use lightweight tags upstream.
- Latest tags: v0.0.9 era. Check `git tag` for current state.

## Conventions to preserve

- **Security-first everywhere**: atomic file writes via temp+rename (`replaceFile` per-OS shims `replace_file_{unix,windows}.go` in several packages), `Lstat` symlink checks before reads/writes, strict JSON decoding (`DisallowUnknownFields` + trailing-data check), size limits on every input, diagnostics scrubbed of config secrets, sentinel errors, `slog` JSON logging.
- Comments explain concurrency/race reasoning — keep them accurate when changing code.
- Time injection (`Now func() time.Time`) for testability.
- Every package has substantial unit tests; integration test in `internal/control/control_integration_test.go` runs full master↔agent over `bufconn` with a fake sing-box via `TestMain` re-exec helper (`THEATROPOLIS_SING_BOX_TEST_HELPER`).
- Minimal, scoped changes; match surrounding style. Update this file when layout, workflow, or conventions change.

## Deploy access

`.deploy/` (gitignored) contains an SSH deploy keypair + `known_hosts` for a live deployment target. Treat as credentials; never commit.
